# Deuda Técnica, Code Smells y Mejoras de Diseño
 
## 1. Code smells / deuda técnica identificada
| ID   | Ubicación (archivo/módulo) | Descripción del problema | Propuesta de mejora |
|-------|----------------------------|--------------------------|---------------------|
| DT-01 | `index.js` vs `index2.js` | El servidor está dividido innecesariamente en dos partes que corren en paralelo. Esto duplica el mantenimiento y deja una sección fuera de la configuración principal (Docker). | Unificar todo en un solo servidor central (`index.js`), moviendo las funciones de organizaciones a su propia sección de rutas y eliminando el archivo duplicado. |
| DT-02 | `db.js` vs `db_organizaciones.js` | Existen dos archivos de configuración que abren conexiones separadas hacia la misma base de datos, lo que consume memoria innecesaria y arriesga colapsar el sistema. | Centralizar la conexión en un único archivo (`db.js`) para todo el proyecto y eliminar el duplicado. |
| DT-03 | Rutas de voluntariados y logros (`index.js`) | Muchas funciones importantes se programaron directamente dentro del archivo principal en lugar de usar las carpetas de organización disponibles, generando desorden y código mezclado. | Limpiar el archivo principal para que solo maneje configuraciones globales y mover la lógica de voluntariados y logros a carpetas independientes. |
| DT-04 | Registro de organizaciones (`index2.js`) | Las contraseñas se guardan directamente en texto plano dentro de la base de datos, lo que representa un riesgo crítico si el sistema sufre un acceso no autorizado. | Implementar una librería de seguridad para encriptar las contraseñas antes de guardarlas y validarlas de forma segura al iniciar sesión. |
| DT-05 | Inicialización de base de datos (`db.js` / `db_organizaciones.js`) | El sistema intenta crear las tablas e insertar datos de prueba automáticamente cada vez que arranca, lo que dificulta cambios futuros y provoca fallos en pruebas. | Separar la creación de la estructura de la base de datos del código de la aplicación, manejándolo con herramientas de migración o scripts externos de un solo uso. |
| DT-06 | Documentación y permisos (`index2.js`) | El campo de correo electrónico está marcado erróneamente como un número entero en la documentación. Además, el segundo servidor no tiene permisos de acceso (CORS), bloqueando al frontend. | Corregir el tipo de dato a texto en la documentación y, al unificar los servidores en el paso DT-01, la configuración de accesos cubrirá todo el backend automáticamente. |
 
## 2. Mejoras de diseño futuras
- **Mejora 1 (Variables de entorno estrictas en Frontend):** Configurar de manera obligatoria y explícita los archivos de entorno en Next.js. *Motivación e impacto:* Evita depender de enlaces fijos grabados en el código si la configuración falla, garantizando que el frontend se conecte siempre al servidor correcto en cualquier entorno de trabajo.
- **Mejora 2 (Modularización de estilos CSS):** Dividir el archivo de diseño gigante (`globals.css`) en módulos específicos por componente visual o adoptar una herramienta como Tailwind CSS. *Motivación e impacto:* Previene futuros choques visuales de diseño y facilita el mantenimiento del código estético a medida que la aplicación crezca en pantallas y nuevas funciones.
